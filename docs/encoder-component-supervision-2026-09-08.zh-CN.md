# Encoder 成分监督：实现完成，采用失败

2026-09-08；起点 4f6f87b。中英文分开，RTX 3080 训练、保存权重重载后 CUDA
float32 校准。没有运行业务任务、调用真实 LLM 或改动生产装配。

## 做了什么

- 单次模型前向产生三种肯定请求、三种否定成分及 needs_planning；不新增 Router。
- 复用 Transformers Trainer 和标准 BCE；unknown 注解通过 loss hook 排除。
- 唯一肯定请求、无同目标否定且无需额外规划，才投影到既有校准/权限/参数策略。
- 在数据来源边界排除 Bitext 宽意图及全部衍生数据；`track_refund` 不能自动当作
  “替用户执行查询”的标签。保留旧数据为历史，不按失败句子添加运行时关键词规则。
- 不把旧 DEFER 反标成所有能力均不存在。按原样本/构造操作恢复可证明的成分。
- 多能力组合双方保持同一 split；general_qa + product_identification 组合不进入
  train/calibration，用开发 heldout 检查组合迁移。

研究借鉴的是[组合泛化评测](https://arxiv.org/html/2603.28929v1)，未复制论文的手工
分句语法，也未声称复现其成绩。[Chain-of-Intent](https://arxiv.org/html/2411.14252v3)
提示应增加真实多轮结构，不意味着复制短答模板即可解决上下文理解。
训练复用[Trainer 官方 loss 扩展点](https://huggingface.co/docs/transformers/v4.46.0/main_classes/trainer)，
没有新增训练循环。上述来源于 2026-09-08 核对。

## 实验过程与结果

最终训练数据：中文 8,374 / 1,586 / 1,034，英文 4,657 / 1,001 / 514
（train / calibration / 已消费 development-heldout）。英文三份源数据分别排除
6,860 / 1,491 / 1,381 条宽标签及衍生记录，**不是从这些数据得出新模型准确率**。

每语言实际训练两次，均 4 epochs、seed 17、lr 3e-5。第一次失败后，修正了
“唯一肯定请求的当前目标 denied 全 mask、双肯定目标却 denied=0”的注解不一致。
这是本次审查仍遗漏过的一项缺陷，不能归咎于模型；第一次数据、模型 metadata 与诊断保留。
第二次仅修此注解，未改变句子、split、阈值标准或超参数。没有第三次训练。

最终校准结果（是禁用前的候选阈值统计，不是线上接受数）：

## 现在剩下的损失在哪里

原始成分诊断（未经过执行门禁）中，中文 37 条、英文 16 条 DEFER 被投影为单目标；
其中中文 36 条、英文 16 条属于两个明确目标，模型漏识别其一。中文一般知识成分
召回率 80.6%，英文 59.1%。英文否定头在当前已标注开发样本上召回为 0，尽管
needs_planning 捕获了相关边界；不能说否定理解已经学会。

因此剩余问题是**成分学习/组合迁移不足**，不能靠把更多功能塞到 Router 或降低
阈值修好。这里只能定位观测到的损失；尚不能将其全部因果归因于数据量、模型容量或
训练轮数。本次同时改变来源和监督，没有对照证据把收益单独归因于多标签方法。

GPU 单次模型 forward 中位数约中文 1.69ms、英文 3.36ms；包含同步取回输出，
不含 tokenization、完整 FastPathPolicy、数据库和 LLM。不是完整链路 P95，且训练/
诊断曾共享 GPU，不作性能采用证明。
