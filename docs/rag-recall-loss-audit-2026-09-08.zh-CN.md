# 低Recall诊断：查询、融合与候选后损失

本轮只复算已消费的MTRAG35组原始排名，API0，不新增模型实验。查询固定为官方改写，不是当前Conversation Agent实时生成的查询；因此本轮不能据低Recall断言该Agent智力不足。

| 阶段 | 宏平均passage Recall |
|---|---:|
| BM25 Top20 | 41.33% |
| Dense Top20 | 61.58% |
| 两路并集，最多40条，仅诊断 | 66.20% |
| 当前融合Top20（Dense权重.25） | 41.33% |
| 候选融合Top20（Dense权重.75） | 61.58% |
| 当前精排/打包Top5 | 33.19% |
| 候选精排/打包Top5 | 44.62% |

35/35题当前候选集合等于BM25，反向权重候选集合等于Dense。单路满20、RRF k10时，主导路第20的独有分数.75/30=.025仍高于弱路第1的.25/11≈.0227；主导路已有20个候选，弱路独有项全部不能进入20。两路重合项可改变排序，所以集合等同不表示排序相同。这解释了候选收益主要来自主导路切换，不能称已充分发挥混合互补。

并集中仍5/35题完全无gold、20/35题缺部分gold。并集剩余33.80个百分点未覆盖，原因需要逐例区分query意图、表达匹配、来源内定位及标注范围；不能直接算作query错误率。并集使用最多40候选，不可冒充同预算改进或生产成绩。

候选策略的61.58%到最终44.62%还损失16.96个百分点；这包括Top20到Top5选择及预算影响，不全算精排模型错误。按当前并集可获得gold计算，理想选五条的宏平均上界也是66.20%；这是使用gold计算的诊断上界，不是可执行策略。

此前四条开发失败证明改写可能修复目标错位，也可能把历史背景加入后让检索回到旧话题；web chat已有正确来源页面命中但标注段落未命中。详见既有query-miss4报告，不把开发见证占比推广到本35题。

下一步使用开发集验证候选保留机制、逐例检查双路遗漏；不在已消费heldout继续扫权重，不根据gold倒写query。生产默认暂不更改，整体答案正确率仍未由这些Recall数字证明。

证据：`artifacts/eval/rag-g4-mtrag-heldout35-2026-09-08/recall-loss-audit.json`（逐题集合与遗漏）、同目录`summary.json`（既有配对指标）。
