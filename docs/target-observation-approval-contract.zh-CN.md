# 工具观测、当前事实与动作准备

2026-09-07；状态：实现验证中，完整对话质量尚未闭合。

## 已确认的因果关系

1. 工具事实原先在 Agent 结果转换时打时间，无法证明真正读取时间；结果板将所有历史返回值当作当前状态。
2. 公开合成与核验直接展开原 AgentResult 历史；恢复任务也会重新注入旧事实，不能只修结果板。
3. 回复降级按每个 Worker 拼接，成功的环境查询没有专用模板时也输出整体不可用，混淆业务与表达失败。
4. 领域中的写工具实际只准备提案，却沿用真正写 API 的名称与描述。业务政策要求执行前确认，容易与准备前置条件混淆。

## 单一职责与支持合同

- ToolManager 在真实 handler 调用前后记录观测区间。缓存保留原区间，artifact/恢复不得重置。
- FactRecord 的证据 identity 绑定值、来源类型、有效期和可信观测区间。重复 identity 的权威元数据不一致是类型化合同错误。
- 没有观测区间的历史数据保留为顺序未知，不根据转换时间推断谁更新。
- ResultBoard 的 current_facts 是派生视图。相同查询、requirement、producer/version 的 VERIFIED_STATE，只有后一次开始晚于前一次结束才可替代。
- 重叠、顺序未知、来源不同的矛盾不会因“取最后一个”消失。同 identity 的矛盾也不被后续读取抹掉。
- 原始 AgentResult、工作消息和工具原文保留。当前规划输入、合成、核验与模板共同使用当前视图。
- 已提交 Receipt 的业务状态不随表达失败改变。不能确认详细文案时说明表达未完成核验，而不是让用户误以为写操作失败并重新提交。
- 领域 Agent 调用 `prepare_<工具名>`，只准备现有 Action。参数不足才 request_user_input；现有审批管理负责展示准确参数、等待决定和执行。
- 真实外部写工具名称、参数、幂等和 Receipt 不变。没有双执行路径，也不把旧原始写名作为领域可调用别名保留。
- 暴露给模型的名称必须唯一；派生 prepare 名称与原子工具/Skill 冲突时拒绝该能力装配。

## 范围与迁移

这是单进程执行时钟能够建立的观测顺序，不宣称跨机器线性一致性或业务数据库版本。
不替代业务系统的实体版本、CAS、授权、缓存有效性及来源撤回检查。
新时间字段为可选字段，旧记录可读但不获得新的时间权威；生产消费者不得从旧记录补造可信观测区间。
旧 checkpoint 若暂停在原名称的领域写工具调用上，需要显式迁移或重新规划，不能借名称兼容绕过审批。

## 参考与验收

核对日期 2026-09-07：[LangChain HITL 官方文档](https://docs.langchain.com/oss/python/langchain/human-in-the-loop)
围绕提议的工具动作暂停、保存状态、根据批准/修改/拒绝继续。这里复用已有 LangGraph 与审批边界，
prepare 命名是为现有应用责任分工消歧的工程选择，不是框架强制 API，也不宣称 SOTA。

验收覆盖：观测置换与幂等投影、并发冲突、缓存不续观测时间、原文 artifact 恢复、
证据 identity 元数据冲突、continuation 不重新注入过期状态、成功写入与表达失败分离、审批一次写入一次。
随后在固定原两条 τ³ 开发任务上记录全部成功/失败、实际写入、最终回复和成本，不以组件测试替代真实语言成绩。
