# 均衡融合的中文本地精排回归

固定20个合成开发query、既有Dense/BM25各20候选，最终20，RRF k10。比较当前Dense .25与均衡 .5。使用预训练BGE reranker（当前本地端口的title+content、不截断、FP16 batch4），无微调。

| 指标 | .25 | .5 |
|---|---:|---:|
| 精排Top5完整span覆盖 | 20/20 | 20/20 |
| 打包5片段/2600 tokens完整span覆盖 | 20/20 | 20/20 |
| 精排/打包文档MRR | 1.000 | 1.000 |
| 精排/打包文档nDCG | 1.000 | 1.000 |

完整span覆盖救回0、误伤0。文档指标按Top5 chunk中来源首次出现去重后计算，与span指标的单位不同。

两个候选池每题合并后打分一次，共441个唯一query–候选评分对；800是两臂位置数上限。441个分数均有限，所有pack ID均在对应精排与评分池内。API0、文档embedding0。scores、顺序、pack ID及模型文件hash已保存。

结论：本组未观察到均衡融合经本地精排后造成误伤。问题与模板语料较接近，不能用满分声称真实电商效果。没有验证Flash精排或最终答案；也不证明两策略在其他数据上等价。

MTRAG开发组已有.25→.5打包Recall@5 42.19→47.14%的结果，可作为均衡策略的另一项开发证据。但MTRAG旧评分使用passage原text，本组使用当前title+content格式，两个绝对分数不合并、不当完全同一管线的跨数据验收。当前生产默认保持.25。

下一步使用第三类已有公共语料WixQA前，先核对本地快照、文档与问题标注粒度、已消费分组；冻结.25/.5及相同本地精排输入格式，不能把已消费问题改名作为fresh heldout。优先零API完成检索与打包验证，再决定少量真实答案测试。
