# 自建中文电商RAG验收：数据与开发基线

用户授权由外部benchmark调参转向自己的电商业务数据。120条模型编写模拟用例已建立：60个规则族，每族两问；40开发/20族、80封存/40族。同族不跨split，不能称120个独立场景。分类为政策30、多轮24、操作26、混合20、边界20；实际不是25/25，按双例分组调整。不能标记真实客户数据或人工gold。

## 已完成

- 60份来源、120条输入/评分记录/业务fixture，全部来源引用及checksum可验证；Agent运行器不读gold。
- 使用Target durable runtime/coordinator、统一历史上下文、PG知识库、真实knowledge handler和业务owner，捕获实际查询、工具输出、最终答复及模型用量。
- 只读业务服务注入每案例订单快照；商品/媒体工具复用API生产工厂，ServiceEpisode返回owner定义UNAVAILABLE。本集合不测跨会话记忆或媒体输入，也不执行退款/取消等写操作。
- 4条校准＋36条开发诊断执行155调用；发现测试入口遗漏领域工具，标记为诊断，未作为正式基线。
- 补齐工具后完整40条开发基线执行155调用，未再出现该能力包缺失。总模型调用310（全部Flash），不把修复环境前后的成绩算成产品收益。
- 数据边界4项测试通过，锁定hash/分组/引用验证通过，正式基线生产源码hash运行前后相同。仍不能把实现检查当语义独立审核。

## 有效开发基线

| 指标 | 结果 |
|---|---:|
| 题数/规则族 | 40/20 |
| 模型可见来源Recall@5 | 92.50% |
| 模型可见来源nDCG@5 | 0.9250 |
| Flash调用 | 155 |
| 输入tokens（含缓存读） | 620158 |
| 缓存读tokens | 371712 |
| 输出tokens | 13544 |

当前60份文档短，gold标在来源层级；每题一个来源，首个相关来源均在第1位或未找到，因此此批两个指标相同。不是完整必要span覆盖、长文档检索成绩或最终答案正确率。多次工具调用按实际顺序收集前5个唯一来源，评分器验证模型输出片段与artifact正文一致。金额费用未按未经核实的单价估计，tokens和调用保留原始记录。

作者逐条复核：27条通过、10条失败、3条需独立复核；67.5%为当前作者确认通过比例，不是最终独立业务通过率。通过不要求原句复述；需复核项涉及新增因果解释、邀请形式和“没查到发票记录”的语义范围。不能为了好看把3条全部计通过，亦不把谨慎的条件表达机械计错。

确认失败包含：7条答复降级/知识部分缺失；另1条仅看订单字段未回答已有改址政策；2条把已发货推为不能自提。具体见author-review.json，逐答案hash绑定。

两个已建立证据的机制：
1. compose提示含引用占位符，模型实际输出了简写引用，发布校验拒绝。这是引用输出合同问题，不能放松合法ID校验或把引用猜回去。
2. 同chunk跨多次查询的score/rank/source_ranks会变化，ResponseAssembler比较整个item产生conflicting evidence identity。下一步应在证据合同owner区分不可变来源正文/版本/位置与查询相关排序字段；不能屏蔽真实正文或版本冲突。
