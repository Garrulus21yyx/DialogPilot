# G3：BM25 执行修复与候选资格对照

日期：2026-09-07。起点 `defe834`。本轮外部 API 调用 0，微调暂停。G3 和整体 RAG 仍未关闭；本报告分别说明已经验证的 SQL 修复和未采用的候选策略。

## R09：相同 BM25 公式，消除重复统计

症状：488 文档的已知失败回放出现 UNAVAILABLE，日志显示词法 SQL statement timeout。触发与机制：原查询的全库／词项统计未强制复用，执行计划可以随数据与规划变化反复计算；首次计划的统计聚合循环达到 11,349 次。不是 embedding 或 Agent 无法理解查询。

责任方为 `PostgresHybridBackend._bm25`，同时服务其支持的检索语料。目标合同：在同一 tenant、generation 和适用范围内计算 n、avgdl、tf、df；复用一次匹配词频表，按原 BM25 公式评分，再关联来源字段；范围过滤、默认超时和类型化失败处理保持有效。候选唯一键保证一条词频记录对应一个文档／词项，df 可由词频表按词计数获得。

修复将 scoped statistics、term frequency、term statistics 显式 materialize，避免重复计算和宽 metadata 分组。求和按 token 固定顺序：中间版本曾出现约 1e-14 浮点误差导致近同分候选换序，因此保留中间产物，并用同样求和顺序的原公式单独核对。最终三条的旧 SQL、固定求和旧 SQL、新 SQL 排名和分数全部一致；不声称所有历史近同分排列都完全相同。

### 隔离数据库实测

488 篇文档、1,469 chunks，三个冻结表达；每组计时三次，表中是中位数。词法专项 Dense 关闭，导入使用占位 hash 向量，不用于真实向量质量结论。旧／新 SQL 在同一个新建数据库和相同参数下比较。

| 表达 | 原 SQL | 新 SQL | 相对加速 | 新 SQL 在 750ms 限制下 |
|---|---:|---:|---:|---:|
| VA 历史表达 | 1,670.89ms | 127.74ms | 13.1× | 132.73ms，20 条 |
| VA 完整表达 | 1,804.25ms | 131.11ms | 13.8× | 138.78ms，20 条 |
| 外籍员工历史表达 | 994.67ms | 171.97ms | 5.8× | 174.20ms，20 条 |

这不是服务 p95、并发吞吐或端到端回答延迟。EXPLAIN／旧 SQL 对照用 30s 诊断预算；新 SQL 另在原 750ms 限制下测试。生产配置未放宽。不同新建库中旧 SQL 耗时波动明显，第一次独立基线曾超过 4 秒；采用同库配对数据，不挑最慢基线计算收益。

验证：21 项数据库／检索／并行相关测试通过。其中生成语料检查独立 BM25 标量公式、重复查询词、查询词序不变性、中文、空文档、无命中、租户和地区过滤；另 5 项候选性质及已知失败回归测试通过。原异常／超时路径未改。尚未做生产部署、并发负载和全量真实向量回放验收。

## R04：固定预算下恢复 Dense 候选参与，仅离线筛选

现有 .25/.75、k10、每路20、最终20，在单查询 BM25 满20时会排斥所有 Dense 独有候选。实验保持评分、权重、K、数据不变，仅比较两路交替取未重复候选，再按原 RRF 分数排序。一路不足时预算交给另一条，不为查询变体新增配额。

数据：已暴露的 Doc2Dial dev300，100文档／314结构chunks，512/64；使用既有 BGE-M3／Python BM25 分数。不是 PostgreSQL、真实 Agent 或新鲜 heldout。

| 指标 | 现有候选资格 | 两路交替资格 |
|---|---:|---:|
| 完整证据 R@20 | 207/300（69.0%） | 218/300（72.7%） |
| MRR@20 | 0.4831 | 0.4854 |
| nDCG@20 | 0.5322 | 0.5417 |

救回21条、误伤10条，净增11条（3.67个百分点）。这说明候选成员选择值得继续，但当前不采用：误伤还没有逐例解释，精排／打包／实际工具可见收益未验证。没有据此更换生产固定权重，也没有声称动态权重或答案准确率改善。
