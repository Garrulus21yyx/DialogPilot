# 同输入规划模型诊断

对 rag-native-context-mixed6 的六份真实规划输入重放 DeepSeek Pro low。逐例程序核对 messages、system、tools、tool_choice、max_tokens 完全一致；模型由Flash变Pro，预算4096，6次API。只测规划，不重跑embedding、检索、生成或业务工具。捕获与比较位于 artifacts/eval/rag-native-plan6-pro-2026-09-06。

结果：两模型均能形成六条可编译计划，均在五条包含知识目标；“质量审核通过是否代表退款到账”均仅选 order_status + refund_status。Pro 在赠品案例取消额外 refund_eligibility 读取，其余目标类别相同。一次抽样不能证明模型间稳定差异，不升级默认模型。

已确认能力说明、上下文和条件要求真实注入。refund_status 的能力说明明确指出进度查询不能代替政策阶段关系解释；生成指令也已要求仅回答当前问题需要的内容。因此继续堆叠同义提示词或直接全链路换Pro，目前没有证据支持。

实际混合入口的生成已经使用 Pro（无thinking，800完成tokens），核验也使用Pro（256完成tokens）。不能把冗长或遗漏统一归因于小模型。核验提示已包含独立目标完整性检查，但对“无法确认到账”的限制性答案允许通过；该问法兼有当前状态与一般关系两种解读，现有评测工具期待并非充分语义判据。

当前结论：
- 订单/政策共享上下文已经进入统一Agent，非“忘记注入上下文”。
- 原生输出改善格式边界，不保证语义需求覆盖。
- 更强规划模型未救回关系问题；暂无默认切换理由。
- 下一步用成对且明确区分“只查当前状态”“只解释关系”“同时要求两者”的新开发问题，验证遗漏还是评测歧义。目标判据应写为信息需求与答案条件，工具名仅作辅助。
- 对冗长问题，先区分必要例外、业务数据限制与无关旁支；不降低证据支持校验、不按字数阈值截答案。

该轮没有改变生产代码，没有端到端准确率增益结论。
