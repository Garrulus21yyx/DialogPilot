## Implementation and evidence

Removed both four-goal constraints from the compiler interchange schema/parser.
The legacy field name goals denotes work proposals, including reads; no separate
business-intent counter now rejects a legal native batch. Existing native six-action
batch bound remains at conversion; runtime scheduling is unchanged. Generated
tests1–6 cover native schema/conversion, policy, compiler, Send inputs and worker
tool execution. No new scheduler or query protocol was introduced.

Operation metadata now has current (goal/preconditions/effects) and remaining_steps
(future tool/target/dependencies). The actual call supplies current tool/target;
no next_step or duplicate current identity is generated. Future edges can reference
the reserved current node. JSON Schema and graphlib check structure, duplicate and
reserved IDs, dependencies, cycles and permissions. Current readiness/combined
feasibility remain semantic checks against tools/evidence, not a structural proof.
64 four-node DAG combinations, invalid contracts, privacy, unchanged operation
identity, proposal checkpoint codec and post-receipt continuation are exercised.

One action_presentation_instruction is derived from runtime-selected proposals for
the existing author and final verifier. Main planning never solicits its own
preliminary approval; it prepares/delegates or consumes an existing decision.
Failed preparation and prior assistant promises cannot establish readiness.
No new model call, language detector, phrase regex or invented approval is added.
Model compliance remains a validation gap; an injected compliant/rejecting stub
only proves rule delivery and handling, not real repeated-confirmation elimination.
