# 电商RAG模拟业务验收 v1

这是模型作者根据项目业务合同编写的模拟店铺数据，不是真实客户会话，不是人工批准gold。120用例/60规则族，40开发（20族）、80封存（40族）。同族两个表达完全同split；第二问测试历史引用，不算独立规则。

`rules.tsv`是模拟规则与评分要点；`corpus.json`导入隔离知识库。`*.inputs.json`仅含用户消息和历史；`*.fixtures.json`给隔离业务服务种子订单；`*.gold.json`只给评分器。运行器不读取gold。知识库包含所有可用来源是正常的；封存问题/答案不能用于调参。

类别为政策30、多轮24、指引26、混合20、边界20。由于按2条一族分组，多轮/指引由原计划25/25调整为24/26。模型作者看过全部编写内容，封存指未运行/未用于调参，非外部盲评。

限制：当前文档短，测业务条件与证据使用，不证明长PDF/表格解析能力。边界题目前是文本规则，不是后端故障注入、真实版本切换/撤回验收；这些仍待增加独立fixture测试。reference span是来源全文，不是最小必要span，当前只计来源Recall/nDCG，不能称完整必要证据覆盖率。语义评分不以关键词匹配或runtime verified代替。历史助手只作为对话，不提升为政策来源。

先运行`PYTHONPATH=. .venv/bin/python scripts/validate_ecommerce_rag_acceptance.py`核查hash、分组、来源和输入隔离。运行4条校准及其余36条开发使用`run_ecommerce_rag_acceptance.py`，仅支持开发，不允许意外运行封存。80题配对须在候选和评分规则冻结后增加明确的解封步骤。
