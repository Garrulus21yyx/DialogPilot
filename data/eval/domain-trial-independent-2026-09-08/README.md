# 独立新鲜上下文试训复核集（2026-09-08）

本集合由独立助手 `trial_fresh_review` 在新鲜上下文任务中直接创作和标注，**不是人类 Gold**，未调用外部教师 API，未进行训练，也未读取本次模型预测。用途是给已冻结的一次性试训提供小规模独立复核，发现单类输出、明显没有学习当前请求语义等失败；不能证明达到 98% 接受精度、广泛泛化或生产可发布。

## 范围与分割

- 中文、英文各 70 条；每语言 calibration / evaluation 各 35 条。
- 每个 split 的六个业务领域及 `__DEFER__` 各 5 条。
- 每条包含 2 条完整、交替的 user / assistant 历史及独立当前用户消息；没有后续答案。
- calibration 与 evaluation 使用不同具体对话场景和措辞，不把同一历史的替代当前回复拆入不同 split；每条有独立 group_id。
- 中英文为对应场景的双语表达，不是 140 个独立语义场景。语言模型应分别报告结果，不把双语合计当作独立样本量证据。
- 覆盖目标延续、显式改域、已完成旧事项、纯结束、自行等待、主动撤回、未解决指代、真正跨域、同域多请求及同业务参数。
- 使用正式输入渲染和固定版本本地 tokenizer 检查 256-token 上限；只加载 tokenizer，不加载分类模型。

本地结构检查通过：140 个 case_id 唯一，各语言跨 split 的完整渲染输入无重复，计数和角色交替均符合上述约束。实测 token 区间：中文 calibration 75–95、evaluation 76–94；英文 calibration 63–75、evaluation 60–77，均含正式 JSON 输入包装和特殊 token。该检查不替代主线对原有数据的重复检查。

`calibration` 只用于冻结模型后的阈值选择；`evaluation` 是本次独立复核，不能反过来调模型、提示词或阈值。每类每 split 仅 5 条，即使全对也不满足现有至少 10 个接受样本的发布门槛，更不构成 98% 统计保证。一次观察后，这批记录不再具有对下一轮迭代的未知挑战性质。

## 创作来源隔离

创作前只读取用户提供的 AGENTS 约束、本地 `AGENTS.md`、`application/domain_encoder.py`、`evaluation/domain_dialogue_teacher.py` 的 RUBRIC，以及 `docs/domain-dialogue-direct-review-2026-09-08.zh-CN.md`。最后一份文档包含少量历史纠正例子，因此这里的独立性是相对于数据文件和预测的独立创作，不声称从未见过任何规则示例。

未读取已有训练、校准、开发数据文件或封存挑战文件；未读取本次预测、成绩、训练日志或模型权重；未依据预测修订样本。为静态审查及长度检查，之后读取训练脚本及相应加载、渲染、骨干版本、采样辅助代码，不执行其中的训练或评测。

主线助手随后独立全文审阅这 140 条的语义，并负责检查与原有数据的输入重复、group 隔离及冻结。该后续审查不应被描述成人工 Gold。

## 训练实现静态审查（不改代码）

审查对象是 `evaluation/domain_encoder_training.py`，并追踪 `_load`、`render_domain_input` 和 `family_indices` 的定义。

- 第 23–24 行要求 CUDA 可用；第 53–60 行使用标准 Transformers `TrainingArguments` / `Trainer`，`num_train_epochs=4`、batch size 24、learning rate 3e-5、fp16；没有另写优化循环。仅静态代码不能证明某次实际运行使用了预期设备或完整执行了四轮，需要对应运行记录佐证。
- 第 29、39–41、52 行的类顺序、模型 id2label / label2id 和每条 labels 数值一致。训练只使用 `splits["train"]`；全历史及当前文本经同一渲染入口送 tokenizer，超过 256 直接失败；未见把所有训练标签覆盖成常量、把文本标签当输入或冻结全部参数的显著实现错误。
- 第 61–63 行保存训练后的模型，再从输出目录加载用于评估，没有显见的重新加载原始骨干覆盖已训权重路径。fp16 保存会损失精度，但没有证据把它视为原始预测单一标签的原因。
- 第 69–77 行在评估后处理中，将超长输入或 top-2 margin 小于 .08 的向量改成 one-hot `__DEFER__`。因此“最终全 DEFER”不能直接推断“原始 argmax 全是同一类”；必须把原始概率/argmax、margin 筛选、阈值接受分别报告。此路径不能解释原始 argmax 全是某个业务标签。
- `family_indices` 只在显式 families 模式下生效，按标签保留原始类数量并在各标签内分配对话族权重；它不进行类别平衡，不能被描述成 class-balanced training。静态审查没有查看实际标签分布或采样结果。
- `logging_steps=200` 对短训练可能没有中途日志；缺少细粒度学习曲线会限制学习失败的定位，但本身不是输出塌缩的证据。

结论：未发现能直接解释原始模型输出单一标签的显著静态实现 bug。训练数据量、优化步数、类别分布、任务难度或实际运行问题仍需独立运行证据；本审查不猜测根因，也不建议据此追加训练。
