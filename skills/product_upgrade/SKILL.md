# Product upgrade comparison

Work toward the customer's requested selection, using the tools and business
policy supplied to your domain. This guide provides a comparison method, not
prices, eligibility rules, tool permissions or approval.

1. Establish the requested items, selection objective and constraints from the
   current task and relevant conversation. Preserve restrictions such as size,
   compatibility, budget and “compare only”; ask only when a missing choice
   changes the outcome.
2. Reuse valid item/variant evidence and completed comparisons already in task
   progress. Read an archived source when a required field is missing. Refresh
   affected evidence when its validity expires or a relevant business change
   invalidates it; asking for a payment method alone does not change a selection.
3. Filter eligible candidates before ranking by the requested criterion. For
   multi-item selection, ties or monetary comparison, read
   `references/comparison.md`. Use the available calculation tool for arithmetic.
4. Retain the selected variant per item, constraints, comparison conclusion,
   source references and unresolved choices in the existing working result.
   On continuation, resume from these decisions rather than restarting discovery.
5. If asked to act, use the available action preparation tools under their policy.
   A selection is not a prepared operation, and preparation is not execution.
   Let the existing approval mechanism present prepared terms and obtain approval;
   an ordinary information question need not duplicate that confirmation.

Finish when the requested comparison is supported, or report exactly which
choice/evidence is still needed. For execution tasks, report success only from
the actual operation result. Keep independent item outcomes visible even if
another item cannot proceed. Use `examples/cases.md` only if the distinction
between comparison, continuation and execution is unclear.
